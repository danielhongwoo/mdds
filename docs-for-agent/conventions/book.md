# 교재 (book) 규약

[규약 목록](README.md) | [book/README.md](../../book/README.md)

`book/`은 학습자를 위한 본문이다. 저자의 작업 계획, 결정, 진행 기록은 `docs-for-agent/notes/`에 두고 섞지 않는다.

**결정: 장 (chapter) 이 유일한 진행 단위다. 장마다 저자 노트 (`docs-for-agent/notes/<주제>.md`) 와 독자용 본문 (`book/NN-slug/`) 을 따로 둔다.**
- 왜: 저자 노트는 체크리스트, 결정, 확인할 것, 진행 기록으로 이루어진 저자용 문서다. 교재는 "왜 필요한가 -> 보기 -> 규격 -> 구현 -> 확인"의 설명 흐름이 필요하고 독자가 읽는다. 한 문서로 두 역할을 하면 어느 쪽 독자에게도 맞지 않는다.
- 버린 대안: 저자 노트를 장 디렉터리 안에 두기 (`book/NN-slug/notes.md`). 독자용 디렉터리에 저자용 파일이 섞인다. 작업 계획을 별도 번호 체계 (phase) 로 두기: 장과 같은 내용을 두 번호로 관리하게 되어 서로 맞춰야 했다.
- 저자 노트는 주제 이름으로 두고 번호를 붙이지 않는다. 한 노트가 여러 장을 맡을 수 있다 (`lab-setup.md`는 1-4장). 장과 노트의 대응은 [roadmap](../roadmap.md)의 표가 유일한 출처다.

## 언어
- 한국어로 쓴다. 기술 용어는 영어 그대로 쓰고 처음 나올 때 한 줄로 설명하거나 [glossary](../../docs/glossary.md)로 링크한다.
- 문자와 규격 인용 규칙은 [markdown.md](markdown.md)를 따른다.

## 장 (chapter)
- 디렉터리 하나가 장 하나다: `book/NN-<영어 slug>/README.md`. 그림이나 데이터가 더 필요하면 같은 디렉터리에 둔다.
- 번호 `NN`은 읽는 순서다. 번호를 바꾸는 비용이 작은 공개 전까지는 자유롭게 고친다. 번호를 바꾸면 roadmap 표와 노트의 "장:" 줄을 함께 고친다.
- 본문은 저자 노트의 작업 (체크리스트, 완료 기준) 을 마친 뒤에 쓴다. 쓰다가 이해가 빈 곳이 드러나면 노트의 "확인할 것"에 적고 돌아간다.
- 장마다 같은 틀을 쓴다 (절 제목도 같게):
  1. 왜 필요한가
  2. 캡처에서 보기
  3. 규격 읽기
  4. 구현
  5. 벤더와 맞춰 보기
  6. 두 벤더는 어떻게 하는가
  7. 연습 문제
  코드가 없는 장 (환경, 관찰)은 4, 5를 뺀다.
- 연습 문제는 캡처 README의 "질문"에서 가져온다. 답은 그 장 안에 있거나, 다음 장을 가리킨다. 문제 옆에 `(캡처 README의 질문)`처럼 출처를 적는다.
- "두 벤더는 어떻게 하는가"에서는 벤더 소스의 파일과 함수 이름, 동작을 설명한다. Cyclone DDS (EPL-2.0) 코드를 옮겨 적지 않는다.

## 코드 스냅샷
**결정: 코드가 있는 장은 장이 끝난 시점의 코드를 `book/NN-<slug>/code/`에 복사해 둔다.**
- 왜: 독자가 본문과 그 장의 코드를 나란히 본다. git을 쓰지 않고도 그 시점의 전체 코드를 받을 수 있다.
- 비용: 같은 코드가 여러 장에 중복된다. 코드를 고치면 그 코드가 들어간 장을 모두 고쳐야 한다. 이 비용을 줄이기 위해 스냅샷은 장 본문의 일부로 취급한다. 장을 고칠 때만 함께 고치고, `crates/`의 코드가 바뀌었다고 해서 스냅샷을 따라 고치지 않는다.
- 버린 대안: 장 끝 커밋에 git 태그. 저장소 하나로 관리되지만 독자가 `git checkout`을 해야 하고 본문과 코드를 나란히 볼 수 없다.
- 스냅샷에는 자기 `Cargo.toml`에 빈 `[workspace]` 표를 둔다 (루트 워크스페이스에 속하지 않게). 검사는 스냅샷 디렉터리에서 [rust.md](rust.md)의 명령을 따로 돌린다.
- 본문에 옮겨 적는 코드 조각은 스냅샷에서 가져온다. 조각 위에 파일 경로를 적는다.

## 라이선스
**결정: 본문은 CC BY-SA 4.0, 코드 (스냅샷과 조각)는 저장소의 `MIT OR Apache-2.0`.**
- 왜: BY-SA는 출처를 밝히고 같은 조건으로 공개하면 복제, 수정, 상업 이용을 모두 허용한다. 이 책을 바탕으로 만든 교재도 열린 채로 남는다. 코드까지 BY-SA로 하면 독자가 자기 프로젝트에 코드를 가져다 쓰기 어려워진다.
- 버린 대안: CC BY 4.0 (파생 교재가 닫힐 수 있다), 코드와 같이 MIT OR Apache-2.0 (소프트웨어 라이선스라 글에 어색한 조항이 있다).
- 고지는 [book/LICENSE.md](../../book/LICENSE.md)에 있다. 규격 인용은 최소한으로 하고 절 번호를 붙인다 (OMG 저작물).

## 목차 갱신
- `book/README.md`의 목차 표에 장의 상태 (집필 전 / 초안 / 완료)를 둔다. 장을 쓰기 시작하면 "초안", 틀의 모든 절이 채워지고 코드 스냅샷 검사가 통과하면 "완료".
- 저자 노트의 산출물 표에 그 노트로 쓴 장을 링크한다.
