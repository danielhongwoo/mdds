# 문서 (Markdown) 규약

[규약 목록](README.md)

문서를 고치는 원칙 (현재 상태만 적기, 결정은 "무엇을 / 왜 / 버린 대안", 진행 기록은 한 줄 색인)은 [CLAUDE.md](../../CLAUDE.md)의 "문서 갱신 규칙"을 따른다. 이 문서는 쓰는 형식을 정한다.

## 문자
- ASCII와 한글만 쓴다. 그 밖의 비ASCII 문자 (화살표, 가운뎃점, em dash, 박스 그리기 문자, 섹션 기호 등)는 쓰지 않는다.
- 대체 표기: 화살표 `->`, `<->`, 가운뎃점 `/` 또는 `, `, em dash `-`, 섹션 기호 `Sec.`, 부등호 `<=`, `>=`.
- 영어 표현은 국제적으로 널리 통용되는 것을 쓴다. 특정 커뮤니티의 은어는 풀어 쓰고, 검색에 필요하면 처음 한 번만 괄호로 원래 말을 적는다 (예: I/O-free core (sans-IO)).

**결정: 한국 개발자가 영어 그대로 쓰는 기술 용어는 번역어를 만들지 않고 영어로 쓴다.** 예: point cloud (점군 X), failover, piggyback, IGMP snooping table (snooping 표 X), flooding (흘려보내기 X), flow (흐름 X), leave (탈퇴 X), query (질의 X). 문서의 표나 메시지의 흐름처럼 일반 한국어로 쓰는 말은 그대로 쓴다. 소리 나는 대로 적는 표기가 널리 쓰이면 그것도 된다 (브로커, 미들웨어, 엔드포인트).
- 왜: 낯선 번역어는 독자가 원래 영어를 떠올려야 뜻이 통하고, 자료를 찾을 때도 쓸 수 없다. 이 책의 독자는 영어 용어로 문서와 코드를 읽는다.
- 한국어로 쓰는 것은 한국어 표현이 이미 널리 쓰이는 경우뿐이다. 예: 직렬화 (serialization), 신뢰성 (reliability), 단편화 (fragmentation), 단일 장애점 (single point of failure), 참가자 (participant).
- 판단이 서지 않으면 영어를 쓰고, 처음 나올 때 한국어로 짧게 뜻을 풀어 준다 (예: failover, 장애가 나면 다른 쪽이 이어받는 것). 번역어를 만들어 영어를 괄호에 넣는 방식 (`점군 (point cloud)`)은 쓰지 않는다.
- 버린 대안: 모든 용어를 한국어로 옮기고 처음에 영어를 괄호로 병기. 번역어가 본문에 남아 계속 어색하다.

## 규격 인용
- `omg-specs/`의 원문으로 확인한 것만 적는다. 형식: `(RTPS 2.5 Sec. 8.4.2.3)`, `(DDS 1.4 Sec. 2.2.3.13)`.
- 원문은 재배포 조건 때문에 길게 옮기지 않는다. 필요한 문장만 짧게 인용하거나 풀어 쓴다.
- 확인하지 않은 내용은 `[추정]`을 붙인다. 조사 노트 (`docs-for-agent/research/`)는 확인한 내용과 추정을 구분해 표시한다.

## 링크
- 저장소 안은 상대 경로로 건다. 절 링크의 앵커는 GitHub 규칙 (소문자, 공백은 `-`, 괄호와 마침표는 빠짐)을 따른다. 예: `### Step 7. 캡처 분석 메모` -> `#step-7-캡처-분석-메모`.

## 다이어그램
**결정: 메시지 흐름처럼 시간 순서가 있는 그림은 Mermaid `sequenceDiagram`으로 그린다.**
- 왜: GitHub과 VS Code 미리보기에서 그림으로 보이고, 원문도 메시지 한 줄씩이라 터미널에서 읽힌다. 문법이 ASCII라 문자 규칙을 지킨다.
- 버린 대안: ASCII 그림. 한글이 두 칸을 차지해 세로선을 표시 폭으로 맞춰야 하고, 한 줄만 고쳐도 다시 맞춰야 한다.
- 구성도처럼 시간 순서가 없는 그림은 ASCII (`-->`, `|`, `+`)로 그려도 된다 (예: [docker-network.md 구성도](../../docs/environment/docker-network.md#구성도)). 한글을 넣으면 폭을 맞춰야 하므로 상자 안 글은 되도록 ASCII로 쓴다.

**결정: 수명, 기간, timeout처럼 길이를 비교하는 그림은 Mermaid `gantt`로 그린다.**
- 왜: 막대 길이로 차이가 바로 보인다 (예: DDS lease 10초와 IGMP membership 260초). 문법이 ASCII이고 GitHub과 VS Code 미리보기에서 그려진다.
- 버린 대안: 표. 숫자는 정확하지만 몇 배 차이인지 한눈에 보이지 않는다. 표는 그림과 함께 두어 정확한 값과 출처를 적는 데 쓴다.
- 작성 규칙: `dateFormat X`와 `axisFormat %s`로 초 단위 숫자 축을 쓴다 (날짜가 아니므로). 막대 이름은 ASCII로 쓰고 (한글은 축 폭이 어긋날 수 있다), 단위를 이름에 붙인다 (예: `IGMP membership 260s`). 같은 시점 (0초)에서 시작해 비교한다.

Mermaid 공통 작성 규칙 (아래 첫 줄은 sequenceDiagram용):
- 메시지 한 줄에 하나. 반복은 `loop ... end`로 줄인다. 설명은 `Note`로 붙이고, 줄바꿈은 `<br/>`.
- 메시지 문구에 `;`, `#`를 쓰지 않는다 (문법 기호와 겹친다). `end`라는 단어도 쓰지 않는다 (블록 끝으로 읽힌다).
- 고친 뒤 GitHub이나 VS Code 미리보기로 그림이 그려지는지 본다.
